Shift renaming log
==================
Generated while aligning shift names in config.py, jet_variations.py, and
tau_triggersetup.py with the CMS Common Analysis Tools naming conventions
(Conventions - CMS Common Analysis Tools Documentation) and the master
systematics list (systematics_master.yml), both from
https://cms-analysis.docs.cern.ch/guidelines/systematics/systematics/

Format: original_name -> new_name   [file]   notes

Convention recap: CMS_<type>_<obj>[_<step>][_<extra>][_<era>], type in
{eff, scale, res, trigger/trig, fake}, obj in {e, m, t, j, b, g, met}.
Theory uncertainties use pdf_*, QCDscale_*, ps_isr/ps_fsr, BR_*, UEPS
(not prefixed with CMS_). Names are kept singular/stem-form wherever the
code appends "Up"/"Down" automatically via shift_map; where the code
already bakes "Up"/"Down" into the name explicitly (no shift_map), the
new name keeps that suffix explicit too, matching the original pattern.

=== Summary of edge cases requiring possible follow-up ===
1. ggH/qqH combined QCD scale / PDF / PS weights in config.py: the same
   shift name is applied whether the sample is ggH or qqH. Consider
   whether these should be split into per-process shifts.
2. CMS_res_m: no exact master entry seen in the fetched documentation
   excerpt, named by analogy with CMS_res_e.
3. CMS_scale_met_recoil_response / CMS_res_met_recoil_resolution: no
   exact master entry for recoil corrections specifically.
4. CMS_l1_ecal_prefiring{Up,Down}: assumed ECAL prefiring source; verify
   against the actual NanoAOD branch used (nanoAODv9.L1PreFiringWeight_Nom).
5. CMS_htt_zptReweight: analysis-specific uncertainty named without a
   known CADI id; convention strictly wants CMS_<analysisid>_...
6. jesUncHEMIssue -> CMS_scale_j_HEMIssue_2018: no master entry for this
   one-off 2018 detector issue.
7. DeepTau version tag for the >=2024 tau ID branch (vsJetDM{dm}pT{pt})
   could not be confirmed against producers/scalefactors.py; kept as
   DeepTau2018v2p5.
8. EleTauTriggerSF / MuTauTriggerSF / DoubleTauTriggerSF: renamed as
   combined "_cross" shifts since one add_shift call varies both trigger
   legs together; master's naming is really meant for the tau leg alone.
9. Four embedding-only trigger shifts in tau_triggersetup.py left
   unrenamed, see "NOT RENAMED" section above.
