ISSUES FOUND AND FIXED (tau_triggersetup.py)
----------------------------------------------
Root cause common to all three: the twiki's per-year trigger tables report DIFFERENT NanoAOD
filterbit indices for the *same* HLT path name across NanoAOD production campaigns (V12 for
2022preEE/2022postEE/2023preBPix/2023postBPix vs V14/V15 for 2024/2025). A single filterbit
value had been reused across all of 2022preEE..2024, matching neither campaign correctly in
two of the three cases:

1. mutau_cross_trigger (HLT_IsoMu20_eta2p1_LooseDeepTauPFTauHPS27_eta2p1_CrossL1), tau-leg
   p2_filterbit: was a single bit "9" for 2022preEE..2024. Doc gives "3, 9" (V12, 2022-2023)
   and "3, 13" (V14/V15, 2024) — the old value matched neither (missing the common bit 3
   for 2022-2023, and wrong second bit entirely for 2024). Fixed per-era.
2. eltau_cross_trigger (HLT_Ele24_eta2p1_WPTight_Gsf_LooseDeepTauPFTauHPS30_eta2p1_CrossL1),
   tau-leg p2_filterbit: was a single bit "3" for 2022preEE..2024 (only the common bit, missing
   the ETau-specific one). Doc gives "3, 8" (V12) and "3, 12" (V14/V15, 2024). Fixed per-era.
3. singletau_trigger_leading/trailing (HLT_LooseDeepTauPFTauHPS180_L2NN_eta2p1): the ORIGINAL
   trigger audit (AUDIT_REPORT_trigger.txt) had already fixed this from a Run2 placeholder to
   this Run3 path, using filterbit "3, 9" uniformly for 2022preEE..2024 — but "3, 9" is only
   correct for the V14/V15 2024 table; the V12 tables (2022, 2023) give "3, 10". Corrected
   2022preEE/2022postEE/2023preBPix/2023postBPix to "3, 10", left 2024 at "3, 9".

PNet-era (2025/2026) filterbits for mutau/eltau/singletau/doubletau, and the 2022-2023
doubletau_trigger DeepTau HPS filterbits ("3, 7"), were already correct against the doc —

Verified src/triggers.cxx's matchParticle(): trigger_bit_values entries are bit *indices*
